# Design

## Context

動機見 proposal.md 的 Why，行為規則見本 change 的 specs。目前與這次變更有關的現況：

- mock 不保存組長，而是每次產生快照時現算：老師有指定（`leaderOverride`）就用指定的人，否則用 `groupJoinedSeq` 最小的人。判定時不看在線狀態。
- 在線狀態是 `sockets > 0`，也可以被測試鉤子 `/__mock/presence` 的 `forcedOnline` 蓋過。連線數在 0 和 1 之間變化時會 `bump()` 推送快照。
- 老師看板用 `PUT /api/activities/:code/groups/:gid/leader` 轉移組長（`TeacherBoard.vue`、`api.setLeader`、`teacherButtons.canSetLeader`、錯誤碼 `NOT_A_MEMBER`）。
- 學生端 `Play.vue` 只讀快照的 `me.isLeader` 與 `members[].isLeader`，自己不推算組長。
- mock 單元測試的 `student()` 和 e2e 的 `joinStudent(..., { open: false })` 只用 REST 加入，沒有 Socket.IO 連線，所以在新規則下算「離線」。
- 介面約定 v1 寫在已封存的 `2026-11-18-switch-to-online-google-sheets/design.md`（G2），以 `build-quiz-buzzer-frontend` 的 D8（v0）為基礎。

## Goals / Non-Goals

**Goals:**

- 讓組長規則可以由後端獨立判定，前端只照快照顯示。
- 組長改變一定伴隨一份新快照，前端不需要額外的事件。
- 現有測試在新規則下仍然能穩定表達「誰是組長」。

**Non-Goals:**

- 不提供寬限期，也不提供「離線多久才遞補」的設定。
- 不調整 Socket.IO 的心跳設定。網路異常斷線要多久才被偵測到，由正式後端決定。
- 不改快照格式，也不新增 Socket.IO 事件。
- 不保留老師手動指定組長的任何形式（包括「鎖定組長」）。

## Decisions

### L1. 組長改為「保存的狀態」，不再每次現算

規則要求「原組長回來也不拿回組長」，所以組長不能只靠「在線且最早加入」現算。若每次現算，原組長一上線就會搶回。mock 改成每組保存一位現任組長（可以是 null），只在下列事件發生時重新判定：

| 事件 | 判定 |
|---|---|
| 成員從離線變在線（第一條連線建立，或 presence 設為在線） | 若該組沒有組長，由這位成員接任 |
| 成員從在線變離線（最後一條連線中斷，或 presence 設為離線） | 若他是組長，改由同組在線且 `groupJoinedSeq` 最小的成員接任；沒有人就清空 |
| 成員換組 | 原組：若他是組長，依「離線」的規則遞補；新組：若沒有組長且他在線，由他接任 |
| presence 設為 `null`（取消強制） | 依實際連線數，套用上面「變在線」或「變離線」的規則 |

判定和 `bump()` 放在同一個同步區塊。這樣快照裡不會出現「組長已離線但還沒換人」的中間狀態，也符合「立即、不設等待秒數」。

實作方式：mock 在每次 `bump()` 推送快照前，對每一組執行同一條規則：現任組長仍在本組而且在線就保留；否則由本組在線、`groupJoinedSeq` 最小的成員接任；沒有人就清空。上表的事件都會呼叫 `bump()`，其他狀態改變（例如開始題目、送出）不會讓這條規則改變結果，所以和「只在上表事件重新判定」完全等價，又不必在每個事件分別寫判定。

替代方案：仍然現算，但記住「上一任組長」來避免搶回。這和保存狀態等價，但條件分散在 `leaderId()` 裡，比較難讀，所以不採用。

### L2. 「在線」的定義維持不變

在線指的是至少有一條 Socket.IO 連線，或被 presence 鉤子強制為在線。同一人開多個分頁時，要全部關掉才算離線。只用 REST 加入、還沒連線的學生算離線，不會成為組長。學生頁面在加入後會立刻連線，所以實際使用時這段空窗很短；選組時如果他還沒連上，組長會在他第一次連線時補上（L1 的第一列）。

### L3. 重新整理不設寬限期

重新整理時舊連線先斷、新連線再建立。依 L1，這段期間有其他在線組員的話，組長會立即遞補給對方，而且不會還回來。這是需求明訂的行為（不保證恢復組長）。考慮過「斷線 N 秒內重連就保留組長」的寬限期，但這違反「不設等待秒數」，也讓前後端都要多處理計時器，所以不採用。

### L4. 介面約定 v1 的差異（交給後端對齊）

| 項目 | v1（原本） | 本 change 之後 |
|---|---|---|
| `PUT /api/activities/:code/groups/:gid/leader` | 老師轉移組長，204；400 `NOT_A_MEMBER` | **移除**（回應 404） |
| 錯誤碼 `NOT_A_MEMBER` | 有 | **移除** |
| `Member.isLeader`、`me.isLeader` | 每組恰好一位（有成員時） | 每組**最多**一位；全組離線時可以沒有 |
| 組長改變時 | 只有老師轉移時推送快照 | 組長每次改變都推送快照（通常和在線狀態改變是同一份） |
| `POST .../submissions` 的 `NOT_LEADER` | 依當下組長判定 | 不變；依後端收到請求當下的現任組長判定 |

快照與事件的欄位都不變，所以前端型別（`web/src/api/types.ts`）不用改，只更新註解。

### L5. 前端只移除操作、補一個顯示

- 看板移除 `leader-select`、`leader-btn` 與相關狀態。`rest.ts` 移除 `setLeader`，`errors.ts` 移除 `NOT_A_MEMBER`，`view.ts` 移除 `canSetLeader`。
- 看板在「有成員、但沒有人 `isLeader`」時顯示「目前無組長」（`data-testid="no-leader"`），判斷寫成 `view.ts` 的純函式，方便單元測試。
- 學生端不需要改邏輯：`studentView()` 本來就依 `me.isLeader` 決定能不能送出；遞補後收到新快照就會出現送出鈕。草稿欄位不受組長改變影響。

### L6. 測試怎麼表達「在線」

- mock 單元測試：`student()` 預設建立一條 Socket.IO 連線（用 `testkit.connect`），讓學生在線，並在測試結束時關閉。需要「離線成員」的測試明確傳入選項不連線，或用 presence 鉤子。
- e2e：`joinStudent(..., { open: false })` 不開頁面，預設用 presence 鉤子把學生設為在線，讓既有「用 API 送出」的測試維持原本的組長。需要離線成員時傳 `online: false`，或之後再用 presence 鉤子設為離線。（實作時調整：原本打算讓 `open: false` 代表離線，但會讓大量既有測試的組長改變，所以改成這樣。）
- 「重新整理時組長被遞補」的 e2e 先關閉頁面、等遞補完成，再用同一個 context 開新頁面。這樣才能確定舊連線的斷線比新連線先被處理；一般的 `reload()` 兩者可能交錯，交錯時組長不會換人，這也符合「不保證恢復」。
- 原本靠老師轉移組長製造 403 `NOT_LEADER` 的 e2e，改成：延遲推送快照，再用 presence 鉤子讓組長離線（`/__mock/presence` 會觸發遞補），讓舊組長的畫面還停在可送出的狀態時送出。

## Risks / Trade-offs

- [網路異常斷線（例如手機休眠）要等 Socket.IO 心跳逾時才會被偵測，預設約 20 到 45 秒，這段期間不會遞補] → 這是傳輸層偵測的延遲，不是規則上的等待。正常關閉分頁或重新整理會立即偵測。是否調整心跳由正式後端決定，記在 README。
- [重新整理會讓組長換人，學生可能覺得意外] → 學生端依快照立即顯示誰是組長；看板也同步顯示，老師可以口頭協調。這是需求接受的取捨。
- [移除手動指定後，老師無法處理「組長在線但不回應」的情況] → 需求明確要求移除。組長可以關掉分頁讓組長遞補，之後可以視需要另開 change。
- [送出請求和組長遞補同時發生] → 後端依收到請求當下的組長判定，前端照原本的 403 `NOT_LEADER` 流程重新取得快照。
- [現有測試大量依賴「只用 REST 加入的學生是組長」] → 依 L6 統一調整 helper，避免逐一修補。

## Migration Plan

1. 先改 mock 與 mock 測試，確認規則正確。
2. 再改前端與 e2e。
3. 把 L4 的差異表交給後端組，等對方確認後，在本文件補上確認結果。
4. 不涉及資料遷移；mock 只存在記憶體，重新啟動即可。回復時 revert 本 change 的 commit 即可。
